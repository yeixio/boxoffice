# Changelog

What changed in Box Office, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). What's under **Unreleased** ships in the `main` image as it merges; releasing renames it to the version, such as `## [0.1.0] - 2026-11-06`, and that section becomes the GitHub release's notes (see [Releasing](README.md#releasing)).

## Unreleased

### Added

- **Importing a whole emulator folder of games works.** Copying in a folder such as an old MAME or AAE install now finds the games in every folder inside it and leaves out the emulator's own folders (`samples`, `artwork`, `snap`, `cfg`, `nvram`, `hiscore` and so on), whose zips are named like the games and used to stop the import. A game named like a different file already in the games folder is now left in the imports folder and listed, and the rest still go in, where before the whole folder stopped at the first one. A copy **From the server** that a restart cut off carries on when Box Office starts again, keeping the files it had finished, and a half-made copy or upload nothing will finish is removed from the imports folder, so it doesn't fill the disk unseen. The guide is [docs/import.md](docs/import.md#importing).
- **Say which game an import is.** On **Import files**, **Change** on a game now asks which game it is as well as the system: type the name to find it on the system's list and pick it, or use the name you typed when the list hasn't got it or there's none (PC games). It goes in under that name; a Switch file keeps its title ID in its name. Box Office fills this in itself where it can, so a Switch download shows as the game its title ID says (`Hades[0100535012974000][v0].nsp` is Hades) and a disc by its serial. A folder of disc images is a game, and one game: Windows discs (with `AUTORUN.INF` or a setup program, as `.iso`, `.bin`/`.cue`, `.img`, `.mdf` or `.nrg`) are told to be a PC game's, and an old game on several CDs goes in whole. An `.iso` with a game on it is no longer taken for a film. API: `PATCH /api/v1/import/item` takes `game`, and items have `game`.
- **Games on every platform.** The Games section now knows about seventy systems: besides MAME and cartridge consoles, disc consoles (PlayStation 1 to 5, Saturn, Sega CD, Dreamcast, GameCube, Wii, Wii U, Xbox, Xbox 360, Xbox One, PC Engine CD, Neo Geo CD, 3DO, CD-i and more), the Switch, DS, 3DS, PSP and Vita, home computers (MSX, C64, Amiga, CPC, ZX Spectrum, Apple II, X68000, PC-98, FM Towns), DOS and Windows PC games. Disc images and downloads are too big to hash, so Box Office reads what's written inside them (a PlayStation disc's serial, a Switch, PS3, PS4, Vita or 3DS title ID, a GameCube or Wii game ID, an Xbox title) from `.iso`, `.cue`/`.bin`, `.gdi`, `.cso`, `.pbp`, `.rvz`, `.wbfs`, `.nsp`, `.pkg`, `.vpk`, `.3ds`, `.cia` and game folders, and matches it against Redump's and No-Intro's lists, or for the Switch the eShop's (from titledb), then by the name in the game or on the file. Those games are **Recognized**. Systems with no list (PS4, PS5, Wii U, Xbox One, PC, DOS) are known by name. A disc in several files, or a game that's a folder, is one game; updates and DLC are listed as such and don't count as the game; a game whose contents say it's for another system says so. **Add a game**, downloads and **Import files** cover them all: downloads are checked by serial or title ID, PC games are searched for in the PC categories, and a disc's tracks or a game folder come in together. Switch games have their eShop icons, PSP/PS3/PS4/Vita games fall back on their own icons, and every system has its RetroArch picture but PC. New setting: `BOXOFFICE_TITLEDB_URL`. The guide is [docs/games.md](docs/games.md#discs-downloads-and-pc-games).
- **Replacements keep the quality of the copy they replace.** When a copy is reported in Matinee as broken, the wrong movie or episode, or in the wrong language, its replacement is now the same quality as the bad copy (a WEB 1080p for a WEB 1080p), or the closest one at the same picture size, and only then a smaller one the profile takes. Releases with a bigger picture, or remuxes for a copy that wasn't one, are turned down and say why, so a 1080p copy no longer comes back as a 2160p remux many times its size and eats into the data cap. Asking for a better copy, another edition, and **Choose a release** aren't held to it. It's on by default: **Replacements keep the same quality** in **Settings → Searching → Missing titles and upgrades** turns it off. API: `GET`/`PUT /api/v1/search/auto` has `replaceSameQuality`.
- **Search for games and download them.** **Add a game** on the Games page finds a game by name in No-Intro's and MAME's lists, in the systems you have folders for or any other, with its versions (the best one, such as the USA release's newest revision, picked for you) and box art. **Want it** lists it under **Wanted** on the Games page and searches the indexers' console and Other categories; releases for another system, packs of many games, soundtracks, PC games and ones too big to be one game are passed over, and **Choose a release** shows what was found and why. Wanted games are looked for again like other wanted titles. Every download is checked by hash against the list before it goes in (a console game, loose or in an archive, even a pack; a MAME set by its ROMs, with its parent, BIOS and devices), and one that isn't the game is quarantined and the next release looked for. The game is copied into its system's folder named as the list names it, the system is checked, and it's no longer wanted. The guide is [docs/games.md](docs/games.md#adding-a-game). API: `GET /api/v1/games/systems`, `GET /api/v1/games/lookup?q=&system=`, `GET /api/v1/games/lookup/art`, `GET`/`POST /api/v1/gamewants`, `DELETE /api/v1/gamewants/{id}`, `POST /api/v1/gamewants/{id}/search`, `GET /api/v1/gamewants/{id}/releases`, `GET /api/v1/gamewants/{id}/art`.
- **Import files you already have.** **Import files** in the sidebar takes files or whole folders uploaded from your browser (or dropped on the page), or picked from a folder on the server and copied in, leaving the originals where they were. Box Office works out what each is from its name and contents: a movie or a show's episode or season (matched on TMDB), an album (`Artist - Album`, MusicBrainz), an ebook or audiobook (`Author - Title`, Open Library), or games, by system. Anything can be changed by hand first. **Import** adds the title to the list if it isn't there (shows, artists and authors unwatched), then files it the way a download is filed; games are copied into their system's folder and checked. Files wait in the downloads folder's `imports` folder, so a restart loses nothing. The Games page has an **Import games** button. The guide is [docs/import.md](docs/import.md).
- **Games: see your video game collection.** Turn on **Games** in **Settings → Library** and add the folder your games are in, and Box Office finds each system's folder (`mame`, `snes`, `gba`… by name, or by the games in it) and lists their games with box art, year, maker, players and genre, under **Games** in the sidebar. MAME sets are checked file by file against the list MAME publishes with each release (the newest, or the version you pick): clones are grouped under their parent, BIOS and device sets are hidden but missed when a game needs one, CHDs are checked, merged, split and non-merged sets are told apart by themselves, and each set is **Complete**, **Missing files**, **Wrong version for MAME 0.xxx**, **Needs a BIOS** or **Not on the list**, with what's wrong on its page. Console games (NES, SNES, N64, the Game Boys, Mega Drive, Master System, Game Gear, PC Engine, Atari, Neo Geo Pocket, WonderSwan) are matched by hash against No-Intro's list, allowing for copier headers and N64 byte orders, with facts from libretro's database. Box art comes from libretro's thumbnails, kept small in the data folder. Nothing needs an account, files are only ever read, and nothing is downloaded but the lists and art. Games are checked when a folder is added, on **Check again**, and weekly; a system on **Do not touch** is left as it was. Off until turned on. The guide is [docs/games.md](docs/games.md). API: `GET /api/v1/gamesystems`, `PATCH /api/v1/gamesystems/{id}`, `GET /api/v1/games?system=`, `GET /api/v1/games/{id}`, `GET /api/v1/games/{id}/art`, `GET`/`POST /api/v1/games/check`, `GET`/`PUT /api/v1/games/settings`.
- **A scanned folder of a title kept in another folder can go in with it.** A root folder scan lists a folder that matches a title already on the list (such as `Cunk on Britain`, which TMDB keeps as season 1 of "Cunk on...") under **On the list in another folder**. Nothing there could be added, so it was a dead end; now **Add its files to <title>** links the folder to the title, without touching the disk. **Problem files** then looks through it together with the title's own folder: episodes or a copy the title hasn't got are moved in and recorded, second copies are listed as duplicates, and the folder is only set aside once no videos are left in it. A second folder named for a title (a garbled name, or an accent written another way) is looked at the same way instead of being set aside whole. A show's file named for another episode by its title, like `Cunk on Earth - S01E01 - In the Beginnings` for season 2's "In the Beginnings", is listed as **named for another episode**, and its fix records and renames it as that one. API: `POST /api/v1/rootfolders/{id}/scan/link`.
- **Restart Box Office from Settings.** Settings → General has a **Restart Box Office** card, for when something seems stuck. After you confirm (it says how many downloads are running), Box Office stops the same clean way it does when Kubernetes or Docker stops it: downloads pause where they are and carry on after, and the stop counts as planned, so no "restarted unexpectedly" alert goes out. In Kubernetes it then exits and the kubelet starts the container again; everywhere else, Docker included, it starts itself again in the same process, whatever the restart policy. The page shows that it's restarting and loads again by itself once Box Office answers. API: `GET /api/v1/admin/restart` (running downloads, and how it comes back) and `POST /api/v1/admin/restart`.
- **The log from before a restart, and the crash that ended it, are kept.** Box Office now writes its log to `<data>/logs` as well as keeping it in memory, and has Go write a crash there too (a panic or fatal error, with every goroutine's stack), so neither goes when Kubernetes deletes the pod. **Health → Log** has **This run** and **Previous run**: the run before shows when it ran, its lines to search and filter as usual, and the crash that ended it, or that it left none (it stopped, or something such as Kubernetes or running out of memory stopped it). The log download for a bug report starts with the end of the run before and its crash. The **restarted unexpectedly** alert now says what the crash was, and a crash shows as a problem on Health after the restart. Each run keeps at most 32 MB on disk, and only this run and the one before are kept. Lines from Go's standard log, such as a web page that panicked, now reach the log too. The Helm chart sets `terminationMessagePolicy: FallbackToLogsOnError`, so `kubectl describe pod` shows the end of a container that failed. API: `GET /api/v1/admin/logs?run=previous` (with `crash`, `started` and `ended`), and the monitor report's `previousRun`.
- **Removing a title cancels its downloads.** Removing a show, a movie, an artist or an author (here, or from Matinee) now stops its downloads that haven't gone into the library and deletes what they fetched: queued, downloading, paused, waiting to unpack, or finished and waiting for **Move into library**. One being checked, unpacked or moved in finishes that step first and then goes the same way. Quarantined, failed and imported downloads, and files already in the library, are left as before. The Remove dialog says how many downloads are cancelled. API: `GET /api/v1/{movies,series}/{id}/removal` has `downloads`.
- **Downloads that couldn't go into the library get another go after an update.** A minute after a new version of Box Office starts, it takes one more go at moving in the finished downloads it tried before and couldn't (they say "couldn't go into the library yet"), so what a newer version knows how to handle, like season packs with scrambled names, goes in without pressing **Move into library** on each. It happens once per version, only while moving downloads in by itself is on, and one that still can't go in waits as before.
- **Specials are searched for when you switch them on.** A show's **Specials** (season 0) were always left out of searches, even with them switched on. Now, once a show's Specials are on, its aired specials are looked for like any other episodes, one at a time (indexers file them as season 0, so searches ask for `season=0`), and upgraded the same way. They stay off by default for new shows, so nothing changes until you switch them on.
- **Season packs with scrambled file names go into the library.** When none of a show download's videos is named for an episode (re-posts often name them with random hashes), Box Office now reads each video's own tags with ffprobe: a season and episode number, or an episode title, are taken as they are, and otherwise the episode summary many web releases carry is compared with the show's episode overviews, within the season the release is named for. A video is only matched when one episode clearly stands out, each episode goes to one video, and a video far longer or shorter than the show's episodes (a double-length special, say) isn't matched by its summary. Videos that aren't any of the season's episodes are then looked for among the show's specials (season 0), whatever their length. Videos it can't tell stay in the downloads folder instead of being cleaned up with it, and the download says how many. In **Files** on the Downloads page, moving one video into a show now has an **Episode** choice for those. API: `POST /api/v1/downloads/files/import` takes `episodeId`.
- **Search by cast.** Typing an actor's name in Discover's search now finds them under **People**, with their photo and what they're known for; each opens a page of everything they're in (movies and shows together, best known first, without talk shows or parts as themselves), each title marked and added as usual. For someone known for directing, it's what they directed. The request site and Matinee's Discover search find what an actor is in too: a search for an actor's whole name puts their best-known titles first, and part of a name adds them after titles named like it. API: `GET /api/v1/lookup/people?q=`, and the Discover row `person-{tmdbId}` (`GET /api/v1/discover/rows/person-{tmdbId}`, also through `/{radarr,sonarr}/api/v3/boxoffice/discover/rows/`), whose page has `person`.
- **Author photos, and books grouped by series.** Authors now have their picture on the Books and Audiobooks lists, on their page and when adding one: Open Library's photo, or the one on Wikidata (from Wikimedia Commons) when Open Library has none. An author's books that belong to a series or collection, such as The Lord of the Rings, are shown together in order (Book 1, Book 2…) above the rest, with **Want the series** and **Want none** for each; a book named after its series, like the one-volume Lord of the Rings, goes with it, and a book's window says which series it's in. Series come from Open Library's series and from Wikidata, looked up in the background after an author is added or refreshed, for authors already on the list soon after starting, and again each month, without holding up searches. `BOXOFFICE_WIKIDATA_URL=off` uses Open Library only. API: books carry `series` and `seriesPosition`, authors `photo`, and `PUT /api/v1/authors/{id}/series/wanted` takes `{series, format, wanted}`.
- **Several editions of a movie, told apart by name or by length.** A movie's page now shows which cut its copy is (Director's Cut, Extended, Theatrical…) and lists the other editions kept next to it, each with its picture, length and size. When a file's name doesn't say, the cut is worked out from how long it runs: a copy at least 5 minutes and 5% longer than another copy is the Extended cut and the shorter one the Theatrical, and a lone copy running 12% and 10 minutes past TMDB's runtime is Extended; these are marked as a guess from its length. A copy made for PAL TV (about 4% short) or a few seconds of logos don't count. In **Problem files**, copies of a movie that are each a different cut are no longer listed as **More than one copy**: they're listed under **Different cuts of a movie**, whose fix, **Keep all as editions**, keeps the movie's copy as it is and records each other cut as an edition, renamed with its `{edition-…}` tag so Matinee, Plex and Jellyfin tell them apart. Nothing is set aside, **Keep one instead** is still there, and editions never set off searches or upgrades. Matinee's edition picker counts editions found by length as owned too. `POST /api/v1/problems/fix` takes `as: {id: "keep_one"}` for these as well.
- **Problems reported in Matinee are fixed by themselves.** When someone reports a movie or an episode in Matinee as the wrong movie or episode, in the wrong language, or with broken picture or sound, Box Office blocks the release the bad copy came from and gets another; the old copy goes to the recycle folder once the new one is in. For the wrong language, Matinee says which language the sound should be in: releases whose names say they're only in other languages are turned down, those that name it come first, and a download whose audio tracks turn out to be in another language again is turned down after downloading, its release blocked, and the next one looked for. The movie's page, and the show's page for an episode, says what was reported and by whom until the new copy is in. Matinee sends these through `POST /{radarr,sonarr}/api/v3/boxoffice/upgrade` with `want: "replace"`, `problem` (`wrong`, `language`, `video` or `audio`), `language` (an ISO 639-1 code, for `language`), `reportedBy` and `fileName` (the reported file: when it isn't Box Office's copy, nothing is replaced, as Matinee may have matched the title wrong), advertised as `problems` in `boxOfficeFeatures`.
- **Problem files shows what's in each copy and part.** For more than one copy and for movies in parts, each file now says how long it runs, its picture (4K, 1080p…, codec, HDR10, HLG or Dolby Vision), its sound tracks, how many subtitles it has and the cut its name or title gives (Extended, Director's cut…), read by FFmpeg during the look. Parts named like `disk_1`, `disk_2` that each run 80 minutes or more are most likely whole copies (another cut or quality) rather than parts, so their fix keeps one (the sharpest, then the longest) and **Join them instead** is a click away; the same 80 minutes Matinee uses to tell parts from versions. `POST /api/v1/problems/fix` takes `as: {id: "keep_one"}` to keep one of a movie's parts instead of joining them.
- **Quality check: Box Office looks inside files for their real quality.** In the background, it reads each movie and episode file with ffprobe (the first time 5 minutes after starting, then new and changed files every 10 minutes, one at a time) to see its real picture size, codec, HDR and sound. Qualities guessed wrong from a name are corrected (a "720p" file that's really 1920×800 becomes 1080p), and files of unknown quality get one, so upgrades compare against what's really on disk. To keep this from setting off a wave of upgrades, only the picture's size is taken as fact: a quality whose size matches is never changed, and where a copy came from (web, Blu-ray) is kept from the record or the name. A file whose source isn't known gets the quality its profile takes at that size that's closest to the profile's cutoff without being below it, so a guess never makes it want an upgrade. Files are only read. **Settings → Library → Quality check** shows how far it has got and what it corrected, with **Look inside every file again**; a movie's File card and an episode's quality (on hover) show the picture and sound and what a quality was corrected from. API: `GET /api/v1/quality-check`, `POST /api/v1/quality-check/again`.
- **Problem files are looked for every day.** Box Office looks through the library folders by itself once a day (the first time 10 minutes after starting, then a day after the last look, yours included; **Look again** still runs one any time), and the page says when the next one is. When a daily look finds problems no earlier look found, it sends an alert saying what's new, by kind, through the alert channels and to Matinee's admins. It's the new **The daily look finds problem files** rule under **Health → Alerts**, on by default. Problems already found, or seen after your own look, aren't sent again, across restarts too.
- **Send ebooks to e-readers.** In **Settings → Send to e-readers** (once Ebooks is on), add a Kindle, a PocketBook or any reader with an email address, and each ebook Box Office downloads is emailed to it once it's in the library; any book can also be sent from its page with **Send to**. The reader's kind is worked out from its address, books go out through the alerts' mail server unless you give another (Gmail, iCloud, Yahoo and Fastmail servers fill themselves in), and **Send a test book** sends a one-page EPUB to check the approved sender. Kindles get EPUB or PDF, since Amazon takes nothing else by email; with Calibre's `ebook-convert` installed (`BOXOFFICE_EBOOK_CONVERT`), AZW3 and MOBI are turned into EPUB first. Each book goes to each reader once, and **Recently sent** shows what went where and why anything couldn't. The guide is [docs/ereaders.md](docs/ereaders.md).
- **Problem files,** under **Settings → Problem files**: a look through the movie and TV library folders for folders and videos that aren't on the list, copies Box Office hasn't recorded, more than one copy of a title, recorded files that are gone, disc images, movies in parts (CD1, CD2…), untidy names and folders, leftovers (samples, programs, shortcuts, partial downloads) and empty folders. Each problem shows what its fix does before you press it, one at a time or all of a kind: rename to `Title (Year)` and `Season 01/Title (Year) - S01E02 - Episode` with subtitles along, record a copy, keep the copy you pick, forget a missing file, or remux a DVD or Blu-ray image, or a movie's parts, into one MKV without re-encoding, checked before the originals move. Originals are never deleted by a fix: they wait in `<library folder>/.recycle/problem-files/`, which emptying the recycle folders leaves alone, until you press **Delete originals** or **Put back** (which also undoes renames and records). Read-only library folders and titles on Do not touch are listed but left alone. API: `GET /api/v1/problems`, `POST /api/v1/problems/look`, `POST /api/v1/problems/fix`, `POST /api/v1/problems/fixes/{id}/putback` and `/delete`.
- **Requests made in Matinee land on the Requests page.** When Matinee is connected to Box Office, what people ask for in its web, phone and TV apps is filed under their Matinee account, the same one they'd use to sign in to the request site, and follows its rules: automatic approval, per-person settings and weekly limits. Matinee admins' own requests are added straight away. Admins can approve or decline in either place. Matinee does this through `/{radarr,sonarr}/api/v3/boxoffice/requests`, advertised as `requests` in `boxOfficeFeatures`; the request site doesn't need to be turned on for it.

### Changed

- **Moving a download to the top starts it now.** When another download is fetching, it makes way: it goes back to waiting just below the ones you moved up, says so, keeps everything it fetched, and carries on by itself from where it was once they're done. Downloads moved to the top don't stop each other; they go in turn. If the month's data cap is reached, the one on goes on as before.
- **Settings is split into sections and can be searched.** The page now has five tabs, **General** (language, TMDB, password), **Library** (media types, root folders, new shows, problem files, recycle folders), **Downloads** (the downloader, news servers, download clients), **Searching** (indexers, quality profiles, automatic searches, data cap) and **Apps and devices** (Matinee, e-readers, Move in); on a phone they wrap as buttons so none hide. **Search settings** (or press `/`) shows every card with a match across all tabs, marks the words found, and names fields that only appear in a card's form, such as a news server's Port. It matches the page's language without minding case or accents, and English too, and also points to Alerts on Health and to Backups. Links to a setting, such as `/settings#news-servers` from Health, open the right tab and bring the card into view; Health's TMDB and root folder fixes now link straight to theirs. E-readers shows a **Turn on Ebooks** button while ebooks are off instead of being missing.
- **The image is now Debian slim with FFmpeg,** in place of distroless, for Problem files' remuxing. It runs as the same user (65532), so volumes and the Helm chart's security settings stay as they are.
- **The README screenshots show real public-domain and Creative Commons titles,** such as Blender's open movies, silent-era classics, the 1940s Superman cartoons, Scott Joplin and Sherlock Holmes, with their artwork credited in [docs/images/CREDITS.md](docs/images/CREDITS.md).

### Fixed

- **Resuming a paused download carries on where it was.** Pausing threw away the part of each file it was in the middle of, so resuming fetched those files again from their start, and a release made of one or a few big files looked as if it started over. Now a pause (or **Pause all**, or Box Office stopping cleanly) keeps those part files and which articles are in them, and resuming fetches only the rest. A part file that's gone, or one left by a crash, is fetched again as before.
- **Importing an emulator's folder works out what's in it.** Box Office knows a MAME or AAE install by its program (`mame.exe`, `mame0154b.exe`, `aae.exe`), and the item is named for it, with MAME's version when the program's name or `whatsnew.txt` says (**MAME 0.154**). Every archive in the install's `roms` folder is that emulator's game, so arcade sets whose chips are named like a console's no longer go elsewhere. AAE has its own system, **Arcade (AAE)** in an `aae` folder, as its sets share MAME's names but aren't MAME's. Only files that might be games are listed as ones Box Office couldn't tell: an emulator's programs, libraries, settings, notes and source code are left without a mention.
- **Arcade games are no longer filed under home systems.** A MAME set whose chips happen to be named like a console's or computer's games (`u42.int`, `vpoker.col`, `mm.a26`) was taken for an Intellivision, ColecoVision, C64, ZX Spectrum or Atari 2600 game. A zip with a short set name and several ROMs in it is now always an arcade set.
- **A file the quality check couldn't read because its share stalled is read again later.** When ffprobe ran out of time on a file (as it does while a network share stops answering), or the share gave an error, the quality check counted the file as unreadable for good and never looked at it again. Now it's marked to try again, and looked inside once more a day later, one file at a time as before; files that are really unreadable, or gone, are still left alone. Files that timed out before this change are retried the same way.
- **Box Office no longer crashes mid-download, starting the download over.** Saving a download's progress read its list of finished files while other files were finishing, which could stop Box Office dead with "concurrent map iteration and map write"; it was then restarted, and the file being fetched started over.
- **Old releases posted under hashed names unpack.** An old-style RAR set (`.rar`, `.r00`, `.r01`…, from RAR 2, whose volumes don't say their order) saved under random hashes that kept those extensions failed with "rardecode: unexpected end of archive" after the first volume, though nothing was missing. The extensions now put the volumes in order, and a file whose yEnc name is a hash is saved under the real name the NZB's subject gives, when that ends the same way. Downloads that failed like this unpack with **Unpack again, without downloading** (one at a time or several with the bulk actions).
- **unrar takes over when the built-in unpacker can't read an archive.** The image now has RARLAB's `unrar` (from Debian's non-free section). When a RAR archive won't unpack, `unrar` is tried on it before the download fails, shown the volumes in order through links in `/tmp`, so the files are never renamed; only plain files come out of it. Without `unrar` on the path (running outside the image), nothing changes. A failure that both can't read says what each said.
- **A news server that can't be reached doesn't fail the download.** When the news servers stop answering (the DNS lookup timed out, say, or the server is down), the download now waits and tries again (after 1, 2 and 4 minutes) keeping what it has, and if they're still away, waits paused saying why and is tried again within the hour, like a dropped downloads share. Before, it failed, and the release was blocked and another looked for, though nothing was wrong with it.
- **The downloads share dropping out while checking or unpacking is tried again.** A read error from the share during the par2 check or unpacking, including a volume whose file handle went stale as it was being read ("read …part08.rar: no such file or directory"), now waits and tries again from checking, like one while downloading, instead of failing the download.
- **A stalled try no longer swaps a volume out from under unpacking.** When a download stalls on the share, it's stopped and tried again; a write of the stopped try that hung could still come back later and put its copy of a file over the one the next try had saved, which on an SMB share pulls the file away from anything reading it (a download failed to unpack this way, though every volume was there). A stopped try's late files are now dropped.
- **Titles with accents or letters like Æ are found and matched.** Releases are mostly named without accents ("Amelie.2001…", "Aeon.Flux.2005…"), so searches and the RSS feed never matched them to Amélie or Æon Flux; now titles and release names are compared without accents, and an indexer is asked for "amelie 2001" rather than "Amélie 2001" when a movie has no IMDb id. Folder names are read the way they were meant: accents written as a letter plus a separate mark (as Macs write them over SMB) and garbled names like `LÃ©on` or `Ãon Flux` are repaired before **Scan** guesses the title, and authors' folders and episode titles in downloads are compared without accents too. The repair Problem files already used now lives in one place (`internal/namefix`) and also puts back a garbled name whose accents were split since, like the `Ãon Flux` folder on a Mac-written share.
- **The Downloads page no longer hangs when the downloads share drops.** When a network share stops answering, reading it can hang for minutes before failing, and the Downloads page, its quarantine list and its file browser waited on it, so they seemed stuck (one wait for the quarantine list ran 7 minutes). Each now waits at most 3 seconds for the downloads folder, then shows the rest of the page with the folder's problem (*isn't answering; check it's mounted and up*), and the next refreshes don't each start another read while one is stuck. Whether a finished download can still be moved in or unpacked again now stops looking at its first file instead of listing all of them, which is quicker on a share.
- **No more "Box Office restarted unexpectedly" after a planned restart.** When Kubernetes, Docker or Ctrl-C stops Box Office, the stop is now noted as soon as it's asked for, so the next start says **Box Office started** even if a download or a slow network share kept it from finishing within its 20 seconds, or it was killed when the grace period ran out. Only a real crash, kill or power cut sends the warning.
- **Releases locked with a password are discarded, not left failed.** Box Office now looks at each archive volume as it arrives, so a release locked with a password, and no password given, is stopped as soon as its first volume is here instead of after the whole thing has downloaded. It's treated like a release gone from the news servers: its files are deleted when **Delete the files of failed downloads** is on (as it is by default), the release is blocked, another is looked for, and nobody is alerted. It's hidden from History behind **Show discarded** (was Show incomplete). A password the release does give, in the NZB or as `Name{{password}}`, is still used to unpack it; if it's wrong, the release is discarded the same way. Releases the indexer marks as locked (Newznab's `password` attribute) are turned down in searches unless they come with the password; before, an indexer's `2` (locked files inside) was taken for the password itself. Encrypted RAR and ZIP archives are found early; a locked 7-Zip archive is found when it's unpacked.
- **Downloads carry on where they left off after Box Office restarts.** Files a download had finished were fetched again whenever the name they were saved as (from inside their posts) wasn't the one in the NZB, which is most obfuscated releases, so those started over from nothing. And a download that was already fetched, and was waiting to unpack or being checked, unpacked or moved when Box Office stopped, was downloaded again from the start, as unpacking had already deleted its archives; now it carries on from checking and unpacking. The file that was halfway through when Box Office stopped is still fetched again from its start, and the progress bar no longer counts it twice.
- **A downloads folder on a network share that drops out no longer pauses the queue for good.** When the share went away, making the folder said "file exists", and download after download was paused for it and stayed paused. Now the queue waits, says on Downloads that the folder isn't answering, and carries on by itself once it answers; downloads paused that way before are resumed then. Checking the folder gives up after 20 seconds, so a hung share can't freeze the queue or the Downloads page. NZBs are now kept in the data folder, so releases can still be grabbed while the downloads folder is away.
- **A download stuck on a hung share no longer holds up the queue.** One that gets nowhere for 10 minutes is stopped and tried again, and writes that never come back are left to finish on their own. A download the share kept dropping out on is paused and tried again within the hour instead of failing, since nothing is wrong with the release, so it isn't blocked.
- **Writing to a slow network share no longer fills the memory limit.** Downloads, unpacks and copies into the library flush every 32 MB and drop what was written from the page cache, so data waiting to go out to the share can't get Box Office killed for running out of memory.
- **Box Office stops within 20 seconds,** instead of waiting on work stuck on a share that stopped answering, which held up restarts and rollouts.
- **A download's folder that another app made, and Box Office can't write in, no longer fails the release.** It gets a fresh folder of its own; and a permissions problem pauses the download instead of blocking a release that's fine.
- **Old RAR sets (RAR 2 era, .rar, .r00, .r01…) unpack when posted beside another archive,** such as subtitles. Their volumes were added to the other archive, and both failed to unpack.
- **Blocked releases moved in from Sonarr and Radarr say why they were blocked.** Those NZBGet failed came over as its raw status line, `{scriptStatus}` and all; they now read as missing articles, password protected, failed repair, duplicate and so on, including the ones already moved in.
- **Jobs cut short by a restart run again** at the next start, instead of ending as failed with "context canceled".
- **Titles TMDB doesn't know any more aren't warned about on every refresh.** They're named in the refresh's result and asked about weekly.
- **One "Disk almost full" alert for one NAS.** Shares of the same NAS read a moment apart were told apart by a few bytes of free space while files were being written, so Health listed the disk once per share and each sent its own alert. The same size with free space within 1 GiB now counts as one disk.
- **Choose a release no longer goes to a blank screen when nothing is found.** A search with no releases came back as `null` instead of an empty list, and the releases window crashed the page. It hit audiobooks first, since indexers often have none, but albums, ebooks, movies and episodes did the same when a search came up empty. Now it says nothing was found.

## [0.1.0] - 2026-11-06

The first tagged release of Box Office: a library manager for movies, shows, music and books that replaces Radarr, Sonarr, Lidarr, Readarr, NZBGet and Overseerr, plugs into Matinee, and moves you over from the old apps without changing them.

### Added

- **Move in from Readarr,** once Ebooks or Audiobooks are on: its authors come across, looked up on Open Library by name, with the books Readarr wants wanted as ebooks or audiobooks, and the copies it has recorded where they are (an audiobook's folder, an ebook's EPUB first). Box Office tells Readarr's root folders of ebooks from those of audiobooks by their files. Its indexers, download clients and blocklist come across too; nothing on disk is moved, renamed or deleted. Like every app in Move in, it can be skipped.
- **Move in from Lidarr,** once Music is on: its artists come across with the albums they want, and each album Lidarr has is counted as on disk where it is, from Lidarr's own track list (with CD folders), or by its folder name. Its indexers, download clients and blocklist come across too; its quality profiles stay behind, since music has its own quality setting. Nothing on disk is moved, renamed or deleted.
- **Every app in Move in can be skipped.** Each one has Skip on the Overview and under its Connect form, and Undo to take it back; a skipped app isn't offered again, and nothing about it changes.
- **Versioned releases.** Pressing Run workflow under Actions → Release tags the next version, publishes `ghcr.io/yeixio/boxoffice:<version>`, `:<major>.<minor>` and `:latest`, pushes the Helm chart to `oci://ghcr.io/yeixio/charts/boxoffice`, and opens a GitHub release with this changelog's notes. `:main` stays the image of what just merged.
- **Box Office speaks Matinee's 32 languages,** in the admin pages and on the request site, right to left for Arabic, Hebrew, Persian and Urdu. People sign in with their Matinee account or one made here, ask for movies and shows, follow them to ready to watch, and report problems. Finished downloads are screened (one with no audio in it is quarantined), then moved to `<artist folder>/<Title> (<Year>)` with their CD folders, covers, cue sheets and logs. Albums already in an artist's folder, as Lidarr left them, count as on disk when the artist is added or refreshed and before each hourly search, so they aren't downloaded again.
- **Search for and download ebooks and audiobooks.** Each book on an author's page has Look for it and Choose a release; wanted books are also searched for by the hourly search. Box Office searches the Newznab ebook (7020) and audiobook (3030) categories, prefers EPUB and M4B, and passes over comics, collections and the wrong format. Finished downloads are screened like movies (a release with no ebook or audio in it is quarantined), then moved to `<root>/<Author>/<Title> (<Year>)`, with Move into library when that's off or fails. Books already in that layout in a root folder count as on disk when an author is added or refreshed. Authors can be set to **Do not touch**.
- **Ebook and audiobook root folders can be scanned too:** each folder is taken as an author, matched on Open Library, and the authors picked go on the list, with their books already on disk counted as there. Nothing on disk is touched.
